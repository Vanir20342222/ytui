## Bugs repaired during review

- Queue import still compared only URL/audio/quality/playlist fields. It silently
  suppressed distinct formats, bitrates, destinations, subtitles and artwork.
  It now uses the same output identity as normal enqueueing. Transport-only
  differences remain repeat-safe.
- Failed/cancelled records blocked importing a fresh request. Those records now
  permit a new queued attempt; importing it again remains idempotent.
- A named pipe supplied as an import path could indefinitely block a worker.
  Import opens without blocking on Unix and requires a regular file within the
  five-MiB limit. Bounded reads still catch files that grow after metadata checks.
- Full collection expansion and watches underestimated retained memory by omitting
  alternate thumbnails and other nested media fields. They now use the shared
  retained-media estimate, including the selected thumbnail copy. Entry, page
  and memory failures still return no partial collection to enqueue.

All four defects were reproduced before repair. Import regressions showed wrong
queue counts and a blocked FIFO reader. A generated loopback JSON response below
16 MiB produced over 16 MiB of retained thumbnail data and was incorrectly
accepted by the old collector; the corrected collector rejects it.

## Fourteen new deterministic tests

Eight import tests cover distinct output requests, processing choices,
failed/cancelled retry, transport-only repeat safety, exclusion of imported hooks/
network settings/destinations, oversized/non-UTF-8 inputs, malformed JSON/late
invalid entries, and FIFO rejection without blocking.

Six collector tests exercise the actual browser parser over loopback HTTP:
multiple pages for both YouTube and Music; continuation cycles; exactly 2,000
versus 2,001 entries; a terminal 32nd page versus an unfinished 32-page catalog;
pre-start cancellation; and nested thumbnail memory accounting. No provider,
browser cookie, keyring, VPN or system setting is read or changed.
